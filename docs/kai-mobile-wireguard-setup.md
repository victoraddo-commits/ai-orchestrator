## 1. Architecture

```
Samsung Galaxy S23 Ultra (10.8.0.8)
    │
    │  WireGuard full tunnel (0.0.0.0/0)
    │  PersistentKeepalive = 25s
    │
    ▼
DD-WRT Router "Ohio" (192.168.99.66)
    │  WireGuard server wg0 at 10.8.0.1
    │
    ▼
Kai Infrastructure (10.8.0.x network)
    ├── 10.8.0.102:8000  — Kai API (Proxmox B)
    ├── 10.8.0.102:8090  — IT Manager
    ├── 10.8.0.102:8006  — Proxmox VE
    ├── 10.8.0.102:8091  — ProxDash
    └── ... other Kai services
```

**Key design point**: The phone routes ALL traffic through the WireGuard tunnel
(`AllowedIPs = 0.0.0.0/0`). This means the phone sees Kai infrastructure exactly as if
it were on the LAN — all DNS resolution, service ports, and internal IPs work
transparently.

### Why full tunnel?
- No split-tunnel DNS leaks — Kai internal hostnames resolve correctly
- Phone can't accidentally bypass VPN for Kai traffic
- Consistent network behavior regardless of cellular vs WiFi

## 2. Phone-Side Configuration

### 2.1 Required Android App
- **WireGuard** (official app, Google Play Store or F-Droid)
- Version tested: latest stable (Android 16 / One UI 8 compatible)

### 2.2 Tunnel Settings

| Setting | Value | Notes |
|---------|-------|-------|
| **PrivateKey** | `<phone-private-key>` | Generated by app |
| **Addresses** | `10.8.0.8/24` | Phone's VPN IP |
| **DNS servers** | `192.168.99.1` (optional, DD-WRT DNS) | Set if Kai uses hostnames; otherwise use IPs |
| **MTU** | `1420` | Standard for IPv4 WireGuard |
| **AllowedIPs** | `0.0.0.0/0` | Full tunnel — all traffic through VPN |

### 2.3 Peer (DD-WRT) Settings

| Setting | Value | Notes |
|---------|-------|-------|
| **PublicKey** | `<dd-wrt-public-key>` | Matches DD-WRT's wg0 private key |
| **AllowedIPs** | `10.8.0.0/24` | Route only Kai network to this peer |
| **Endpoint** | `<home-public-ip>:51820` | Home WAN IP + WG listen port |
| **PersistentKeepalive** | `25` | Keep NAT mappings alive, detect tunnel drops |

### 2.4 Android App Configuration

1. **Auto-start on boot**: Enable "Apply on boot" in WireGuard app
2. **On-demand activation**: Enable "Always-on VPN" in Android VPN settings for the
   WireGuard profile
3. **Block connections without VPN**: Enable for full tunnel to prevent leaks
4. **Battery optimization**: Disable battery optimization for WireGuard app
   (Settings → Apps → WireGuard → Battery → Unrestricted)

## 3. DD-WRT Side (Verified)

The DD-WRT router "Ohio" (192.168.99.66) is the WireGuard server. Configuration is
managed by Kai's `core/wireguard_manager.py`.

### 3.1 Access
- **Protocol**: Telnet (port 23)
- **Command limit**: 500 characters per command
- **ANSI codes**: Output includes terminal escape sequences — Kai's parser strips them
  automatically (`_strip_ansi()` in `wireguard_manager.py`)

### 3.3 Health Monitoring

Kai monitors the phone's VPN health through two channels:

1. **Device heartbeat** (30s interval): Phone sends `vpn_ip: "10.8.0.8"` in heartbeat
   data. Kai queries DD-WRT for peer handshake age and reports status:
   - `connected` — handshake < 90s
   - `degraded` — handshake 90-300s
   - `offline` — handshake > 300s or peer not in table

2. **Separate WG health endpoint** (`GET /kai/wireguard/health`): Full tunnel and peer
   health for all WireGuard peers.

## 5. Troubleshooting

### Phone shows "connected" but Kai unreachable
1. Check Kai API is running: `systemctl status ai-orchestrator`
2. Verify phone can reach Kai: open `http://10.8.0.102:8000/docs` in phone browser
3. Check DD-WRT firewall isn't blocking: telnet to router, `iptables -L | grep wg0`

### Handshake age grows without bound
- Phone's WireGuard app may be paused by Android battery optimization
- Check: Settings → Apps → WireGuard → Battery → Unrestricted
- Also ensure "Always-on VPN" is enabled in Android VPN settings

### No peer visible in wg show
- DD-WRT may have restarted without restoring WireGuard config
- Kai's WireGuard manager should auto-recover on `/kai/wireguard/recover`
- Manual: telnet to DD-WRT, run `wg show wg0`

### 500-char command limit errors
- Kai's `wireguard_manager.py` already handles this by splitting long commands
- If seen during manual telnet, use shorter quotes or break into multiple commands
